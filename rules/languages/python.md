# Python 通用规范

本文件定义 Python 语言、工具与代码层面的通用约束。仓库内更具体规则优先。

## 适用范围
- 默认遵循项目声明的 Python 版本；未声明时使用 Python 3.12+。
- 环境与依赖优先使用项目已有工具；未声明时默认使用 `uv`。
- 改动保持最小且局部，不顺手重构无关代码。

## 工作流程
- 编辑前先读相关文件。
- 行为不明时，先看现有实现并对齐。
- 新能力、破坏性变更、架构变化、规范工作按项目既有流程推进。
- 改动后跑最小相关验证，并报告跑了什么、没跑什么。

## 代码风格
- 遵循 PEP 8，可读性优先于炫技。
- 命名显式；除非缩写已经是项目约定，否则不缩。
- 函数短小聚焦；嵌套过深用 guard clause 或提取函数。
- 注释只写非显而易见的意图、权衡或约束，不做复述。
- 源码默认 ASCII，除非已有非 ASCII 场景。

## 类型
- 新增或显著修改的公开函数、方法、模块级常量加类型注解。
- 优先使用内置泛型（`list[str]`、`dict[str, Any]`）与新联合语法（`X | None`），不用 `typing.List` / `typing.Dict` / `Optional[X]`。
- 合适时使用 `Protocol`、`TypedDict`、`dataclass`、`Enum` 提升正确性与可读性。
- 避免过宽以致失去意义的注解（如随处 `Any`）。

## 枚举与常量
- 固定取值的字段（type、status、level、role 等）使用 `Enum`；字符串值优先 `StrEnum`，整数值优先 `IntEnum`。
- 不用散落的字符串字面量表达同一类取值。
- 对外序列化时明确枚举的底层值契约。

## 导入与模块
- 分组排序：标准库、第三方、本地。
- 默认使用绝对导入，除非包内已明确使用相对导入。
- 除显式入口外不引入 import 期副作用。
- 避免循环依赖；共享逻辑下沉到更小的模块。

## 数据建模
- 简单结构化内存数据优先 `dataclass`。
- 只有行为与状态确实绑定时才用类。
- 序列化、校验、业务逻辑尽量分离。

## 错误与日志
- 抛具体异常，避免宽泛的 `Exception`。
- 错误信息要可定位原因。
- 不静默吞异常。
- 用 `logging`，不在库或应用代码里留 `print`，除非是明确的 CLI 脚本。
- 不记录 secrets、token、密码、凭据原文。

## 异步与并发
- IO 密集任务优先 `async/await`。
- 异步代码里不允许阻塞调用（阻塞 IO、`time.sleep`、同步锁长占用等）。
- 必须调用阻塞或 CPU 密集代码时，下放到线程池或进程池隔离，不污染事件循环。

## 测试
- 新行为与缺陷修复补或改测试。
- 测试确定性：避免真实网络、时间依赖、隐式全局状态。
- 测行为与契约，不测实现细节。
- fixture 和 helper 就近组织，除非共享已经成体系。
- 禁止为测试通过而修改生产代码结构，尤其是新增 test-only 分支、参数、接口或状态。
- 代码难以测试时，优先重构边界与依赖；不要通过侵入业务代码、强打桩或补丁绕过问题。
- 测试应面向公开契约与稳定边界，避免硬编码易变常量，避免耦合私有实现与脆弱细节。

## 依赖
- 标准库够用就不引第三方。
- 需要三方能力时，优先使用成熟、活跃维护的主流第三方库，不重复造轮子。
- 复用已有依赖，不引入近似重复包。
- 新增依赖必须说明价值是否覆盖其维护成本。

## 性能与安全
- 非性能任务不提前优化；优化前先定位真实热点。
- 大输入输出走流式处理，不一次性加载到内存。
- 在边界校验不受信输入。
- 文件、子进程、网络操作显式、最小作用域。

## CLI 与脚本
- 路径用 `pathlib`，不做手工字符串拼接。
- CLI 返回正确退出码。
- 入口函数保持薄，业务逻辑下沉到可测函数。
