# 常规深度报告

## 目标

将已验收的研究结果组织成一篇可发布的公司深度报告。读者默认了解公司的基本业务。

## 章节

按以下顺序写作；没有可靠数据时说明缺口，不以泛泛叙述替代。

1. 行业与公司位置：行业规模、增长、价值链、竞争位置。
2. 业务概览：收入结构、关键财务指标和长期趋势。
3. 核心业务：主要收入驱动、竞争位置与基础风险。
4. 利润基础：高利润、可持续的业务或收入来源。
5. 增长业务：已实现收入、增长驱动、竞争与兑现风险；区分管线和收入。
6. 管理层与文化：决策记录、资本配置、激励、持股与组织能力。
7. 财务与估值：PE、EPS、FCF、ROE、GAAP 与非 GAAP 差异、历史和同业对比；有合格数据时加入一致预期 EPS 与远期估值。
8. 风险：竞争、执行、供应链、客户集中、监管地缘、稀释、估值压缩和关键人。每项写明机制、触发信号与可能后果。
9. 投资者七问：利润能否持续、增长是否真实、管理层是否与股东站在一起、最坏情况、最好情况、地缘与监管风险、适合什么样的投资者。

## 图表

优先用图表呈现时间序列和结构数据；摘要、比较和清单信息用图片表格呈现，最终文章不得使用 Markdown 表格。按数据可得性优先生成：

- 收入结构；
- 收入、净利润、毛利率、经营利润率、ROE 的 3–5 年趋势；
- 现金流与净利润；
- 历史 PE、远期 PE、GAAP/Non-GAAP EPS（可获得时按最近 12 个财季）；
- 同业 PE、利润率、ROE 或 EV/Sales 对比；
- 一致预期 EPS 路径（仅使用下游技能提供的结果）。

趋势、结构和关系数据使用 `pie`、`bar`、`line`、`combo` 或 `grouped_bar`；比较型或摘要型信息使用 `table`。业务结构图、关键里程碑时间线先展示图，再解释。趋势图、同业比较图先提出要解释的问题，再紧跟图表和分析。同一位置连续放置不超过两张图片。

收入或业务结构的解释先放结构图，再在图后说明核心业务、非核心业务和各自的财务影响。金额可靠时，使用 `pie --amount-and-percentage --amount-unit B`，在同一图中展示每项业务的美元收入与占比；纯占比图才使用 `pie --percentage`。若核心业务占比极高，图表必须清楚标出核心与其他业务的比例。未并表的权益法投资不得当作集团收入展示，应在图后说明其持有方式、盈利状态和影响范围。

当 3–6 个公司里程碑能解释当前业务、管理层或资本配置逻辑时，使用 `timeline` 展示；不为罗列公司历史而生成时间线。

报告必须从主技能根目录使用 `templates/cover.html` 和 `scripts/gen-covers.sh` 生成 `cover.png`，并将其置于标题与正文之间。

## 写作规则

- 每段以事实或直接判断开始；判断必须紧随证据。
- 清楚区分披露事实、推断与数据缺口。
- 使用 `$K`、`$M`、`$B` 等美式单位，不换算为“万”或“亿”。
- 不写工具名、验证命令、过程性免责声明或“AI 研究”话术。
- 不使用填充性引导语；不使用无证据的形容词。
- 专业术语首次出现时，在括号内给出准确的白话解释；不为追求通俗而省略必要的分析。
- 保留九节分析框架；避免所有段落采用相同的“数据—结论—风险”句式。
- 使用自然的分析语言，允许明确判断和有节奏的长短段落；不使用“需要指出的是”“从多个维度看”“综上所述”等模板化过渡句。
- 文末以斜体写一段数据说明，列出关键来源、截至日期、口径差异和未解决缺口；不写校验过程或工具。
