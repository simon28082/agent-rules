# 财报分析

## 目标

将单季财报数据、管理层表态和估值更新组织成一篇可发布的季度分析文章。读者默认了解公司的基本业务，不需要从零介绍。

不同于深度报告，财报分析回答的核心问题是：**这个季度的新信息是否改变了公司的投资判断。** 不追求面面俱到，但每个结论必须有证据支撑。

## 章节

按以下顺序写作；分节标题可根据内容调整，但分析逻辑不变。没有可靠数据时直接跳过对应章节。

### 1. 核心数据

一句话概括当季最重要数字（收入、利润、自由现金流、基建投入等核心指标的变化方向）。然后给出收入结构和利润与现金流的两个概述列表，让读者在 30 秒内掌握全局。

只列出最关键的指标；不穷举费控明细、资产负债表细项或非核心经营数字。

### 2. 值得关注的变化

本季度 2-3 个最重要的新信号。每个变化写一段即可：发生了什么、什么原因、为什么重要。不要平均用力——真正重要的信号写详细，次要的合并或省略。

常见选题：业务增速拐点、利润率突破、现金流转折、新产品/新客户、重大指引变化。

### 3. 管理层表态

电话会上 CEO/CFO 提供的定量信息和口径变化。只写有信息增量的内容：

- 管理层给出了哪些以前没有的新数字
- 管理层对增长、竞争、投资的判断是否有方向性变化
- 管理层主动承认了哪些短板或风险

不列席分析师问答的具体对话；只提炼对判断有实质影响的信息。

### 4. 与同行的比较

关键指标的横向对比：PE、增速、利润率、自由现金流状态、基建投入规模。如果本季度没有足够可靠的同行数据，跳过本部分。

### 5. 前瞻估值

基于最新财报更新估值数据。包含：

- 当前股价、市值、股本
- 分析师一致预期 EPS（当前财年和未来 1-2 年）
- 对应的远期 PE
- 价格敏感性分析（基于 PE 倍数的不同情景）
- 分析师目标价范围（来源明确）

估值数据只能来自下游技能（financial-data）的交叉验证结果。没有合格数据时，只说明缺口，不自行推算。

### 6. 核心信号与跟踪点

- 列出本季度传递的 3-5 个核心信号（这份财报确认或改变了什么）
- 列出 3-5 个需要持续跟踪的观察点（下季度、下一披露节点需要盯什么）

## 图表

遵循主技能的数据边界和图表规则：

- 最终文章不得使用 Markdown 表格。比较型或摘要型信息使用 `table` 子命令生成 PNG。
- 收入结构优先使用 `pie --value-type currency --value-unit B`，在同一图中展示美元金额与占比。
- 趋势数据（多季度的利润、利润率、EPS 变化）使用 `line` 或 `combo`。
- 同行对比使用 `table`。
- 价格区间分析使用 `table`。

**每篇文章至少包含两张图：** 收入结构（pie）和同行对比（table）。其余根据可用数据灵活增减。

图表和表格图片紧跟首次解释该数据的段落；同一位置连续放置不超过两张图片。

报告必须生成封面：使用 `templates/cover.html` 和 `scripts/gen-covers.sh`，以已验收数据填充封面指标，并将 `cover.png` 置于标题和正文之间。

## 写作规则

- 每段以事实或直接判断开始；判断必须紧随证据。
- 清楚区分披露事实、推断与数据缺口。
- 使用 `$K`、`$M`、`$B` 等美式单位，不换算为"万"或"亿"。
- 不写工具名、验证命令、过程性免责声明或"AI 研究"话术。
- 不使用填充性引导语；不使用无证据的形容词。
- 专业术语首次出现时，在括号内给出准确的白话解释；不为追求通俗而省略必要的分析。
- 保持直接、中性的分析语言。直接陈述事实，不加情感修饰。不使用"报告中的关键事实""需要指出的是""从多个维度看""综上所述"等模板化过渡句。
- 允许明确判断和有节奏的长短段落，避免所有段落采用相同的"数据—结论—风险"句式。
- 标题使用中性陈述，不使用感叹号、问号或夸张修辞。
- 成文后必须读取并按 [发布文末](publication-footer.md) 写入最后两段，再运行 `scripts/validate-report-footer.py <报告路径>`；校验失败不得交付。
